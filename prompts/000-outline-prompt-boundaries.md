# Outline Prompt Boundaries

Governs every format outline prompt in this folder. Read before building or editing one.

## The job

One outline prompt per format planner in `knowledge/format-planners/`. Seven total: case-study, deep-dive, interview, listicle, news, roast, short-process.

Each is Billy's parable/principle/transition outline prompt adapted to how that format actually builds a body. Nothing more.

One planner per turn. Billy verifies before the next one starts.

## The test

Does it change what goes in the outline, or where it goes? In bounds.
Is it about how it looks or performs on camera? Out of bounds.

Marking where a client's confirming line lands is placement, so it stays. "Avoid cinematic production" is an edit note, so it goes.

## In bounds

- The body, from the first unit to the last
- Whatever the planner names as its structural units, in the planner's own words
- The order those units go in
- What each unit must contain
- Transitions between units
- Rules that determine which material makes the cut (one transformation, cut side missions, stage match)
- Gap flagging in brackets
- Where proof or evidence lands in the outline

## Out of bounds

Every planner carries these sections. None of them belong in an outline prompt.

- Hooks. Any type, example, or advice.
- Intros. Opening lines, the universal intro template, intro adaptation tables, viewer's top 3 questions.
- Endings. CTAs, conversion strategy by goal, end screen routing, lead magnets, offer mentions.
- Titles. Including the title formula lists.
- Thumbnails. Strategy, text, packaging.
- Goal selection. Sales vs emails vs views.
- Format selection. When to use this format, creator level gates, format scoring.
- Production and edit notes. Talking head vs cinematic, b-roll, footage handling.
- Distribution. Description links, pinning, email nurture, compounding strategy, upload and tracking.

The prompt starts where the body starts and stops where the body stops. Everything on either side belongs to another skill.

## Where the output goes

Every one of these prompts writes a file. Handed a braindump file, the prompt creates `script.md` in that same folder and puts the whole outline in it. Not outline.md. Not a response the creator has to copy out.

Frontmatter matches the existing vault convention: type, slug, piece and source wikilinks, format, status, created, last_updated, tags. Carry over project and department from the piece file when one exists. Never invent a value for a field with no source.

Handed pasted text instead of a file, the prompt returns the outline in its response.

## Construction rules

**The planner supplies the structure and its words.** If it says Problem, Action, Outcome, use those. Do not invent a layer on top of the planner's own vocabulary. Inventing "beats" for the case study was the first violation and the reason this file exists.

**The original prompt supplies voice and bones.** Keep the role line, the YOUR ROLE line, the no-questions rule, Simplification Principles, bracketed gap notation, the OUTPUT FORMAT block, and the Remember close.

**Parable, principle, and transition are the three words.** Do not rename them. Do not add a fourth.

**Style.** Second person. Short sentences. Examples in quotes. Plain words over spec writing. No em-dashes. No AI slop patterns.

**The prompt never asks questions.** That constraint carries into every variant.

## Escalate instead of deciding

Bring these to Billy rather than resolving them alone:

- A format where one of the three words genuinely does not fit. News splits its body into What Happened, Why It Matters, and What Viewers Should Do, and interview hands the parable to a guest. Show the problem before dropping a word or forcing one.
- Anything sitting on the line where the test above gives an unclear answer.
- Any moment that would require a term the planner does not supply.
