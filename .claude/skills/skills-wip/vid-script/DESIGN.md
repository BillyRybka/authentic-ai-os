# Design notes: vid-script

## What the live test changed

The first build bet on zero reference files: one lean SKILL.md, craft as internalized prose, examples inline. A blind head-to-head against the old procedural skill lost on the dimension the lean build had no depth for: flow. The winning draft read as one continuous spoken thought, with personality living in the connective tissue between points, because that skill wrote with a catalog of worked transition sentences in context. The lean draft was tighter and had the better exit hook, but read stacked: correct sentences that did not need each other.

Two conclusions, and only one of my original theses survived:

1. **Depth in context wins.** For a creative skill, worked examples are not documentation, they are the writer's working memory. More good calibration in context at draft time produces better prose. Zero references was a purity bet, and the test priced it. References are the advantage.
2. **The compliance thesis still stands.** What made the old skill weak was not its reference files, it was checklists and decision matrices that let the model satisfy the rubric instead of the writing. So the rebuild keeps references as calibration to write FROM (worked examples, dead twins, catalogs) and still contains no checklist to grade against.

Two craft corrections from the creator are also baked in:

- **Parable and principle are two bricks, not a mandatory pair.** The old "every point has two halves" rule is gone. The pairing frequency is the structure's call: some videos run one parable arc up front (sometimes in the intro) and every later point as pure principle, because the arc already earned the belief. The law as written: parable where belief is needed, never forced where it isn't, never withheld where doubt lives. The Deep Dive format line carries the same flex, and "the forced parable" joined the deaths list.
- **Flow is first-class craft.** A new section in SKILL.md defines the fabric (one continuous spoken thought, every line reaching back or handing forward) and the four moves: reach back, reason forward, deny then deliver, direct asides. Its death, the stack, leads the deaths list, with the shuffle test to detect it.

## The file map

```
SKILL.md                  The judgment core. Bones, craft as prose, when to load which reference.
references/
  flow.md                 The connective craft. Four flow moves worked with dead twins, the full
                          handoff catalog (intro to body, point to point, payoff to re-hook, story
                          to principle, principle to proof, body to ending), and the stacked vs
                          woven pair. Loads before drafting any prose, every session.
  gallery.md              What good looks like. Five worked examples with dead twins: full deep-dive
                          segment, varied listicle parables, lean vs hard short-process steps,
                          payoff then re-hook, the segment handoff. Loads before drafting any
                          prose, every session.
  formats.md              Per-format calibration for all seven formats: identity, weighting,
                          energy, worked notes, dead twin each. Loads when the outline names
                          the format (that format's section).
```

Load timing is mandatory, not "when needed." The test showed the cost of depth arriving late: it never arrives. flow.md and gallery.md are pre-draft reads every session; formats.md loads per video. The gallery moved out of SKILL.md because the reference mandate removed the reason to inline it (the load is no longer a bet on timing), and moving it let both it and the flow catalog grow past what a single readable SKILL.md could hold.

**The firewall travels.** All three references contain generic-creator examples, so all three open with the same rule: steal the moves, never the sentences; any phrase, rhythm, or name that leaks from a reference into a draft is a bug by definition. SKILL.md states it once more where the references are introduced. Runtime voice has exactly two sources: the creator's reference passages and the brain dump's verbatim phrasing.

**flow.md is built around one running example** (an invented follow-up system video with a client named Dana), on purpose: a catalog whose own entries reach back to each other demonstrates the craft it teaches, and a persistent world is what the reach-back move needs to be shown at all.

## What stayed from the first build

- **The three bones.** Input gate (brain dump, outline, reference passages; missing input gets asked for, never substituted). Pre-write read (central question and its 60 to 80 percent payoff, loops, where belief is needed, handoffs). Read-aloud loop (short turns, creator's rewording wins verbatim, nothing final without their yes).
- **Craft as prose, not procedure.** No numbered workflow, no per-format templates, no edit checklist. The deaths list is a diagnosis kit for flat drafts, not a pre-flight check, and most deaths point to a worked dead twin in a reference.
- **Scope negotiated in one line.** Propose when obvious, ask once when not.
- **[VISUAL: ...] notes** as the only markup, so the creator has the capture list before filming.
- **Truth verbatim.** Numbers and stories trace to the material exactly; holes get surfaced, never filled.

## Still deliberately left out

- **Checklists and decision matrices.** The compliance failure mode the rebuild exists to avoid.
- **Length targets and word counts.** "A beat is too long the moment the viewer got it" remains the length rule.
- **A retention-theory primer.** The physics stays imperative; no essays on why.
- **Any instruction to hunt for context** beyond the three inputs and the skill's own references.

## Vocabulary

All shared names preserved: parable and principle, the parable types (Story with Problem/Action/Outcome, Visual Demo with Show the Problem, Contrast, Breakdown, Metaphor), open loops, setups and payoffs, forward hook, re-hook, brain dump, the read-aloud test, and the seven formats by name. New named craft introduced by this build: the four flow moves (reach back, reason forward, deny then deliver, direct asides) and the stack as their death.

## Round-two revision: the hybrid (2026-08-27)

The rematch (rebuilt vid-script with self-authored references vs vid-segment, blind read on a lean principle-led segment) went to vid-segment again. The creator's reason: more personable, more engaging, more human behind it. The rebuilt draft flowed but ran at one speed and repeated its walking beat.

Diagnosis: the writing gap tracks the corpus gap, not the process gap. vid-segment writes from the creator's proven knowledge corpus (prose-craft, voice-rhythm, attention-craft, transition-patterns, tension architecture, format planners), distilled from the source method over months. The self-authored references were one sitting old.

The revision, made directly in the vault, keeps this skill's process (three bones, pre-write read, read-aloud loop, diagnosis not checklists) and rewires the reference layer onto the proven corpus:

- Always before drafting: references/flow.md, references/gallery.md, knowledge/prose-craft.md, knowledge/voice-rhythm.md, knowledge/attention-craft.md
- Per video: knowledge/format-planners/{format}.md, knowledge/script-tension-architecture.md
- At boundaries: knowledge/transition-patterns.md
- references/formats.md deleted as superseded by the format planners (preserved in the session build directory)

flow.md and gallery.md survive as this skill's own contributions: flow because it names first-class craft the corpus never isolated, the gallery because inline worked examples were the one bet the tests confirmed. The knowledge/ files are shared with other skills: read, never edit.
